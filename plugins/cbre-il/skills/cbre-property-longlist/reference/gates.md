# The gates

Same principles as `cbre-il-account-briefing`: **author != reviewer** (judgement -> isolated sub-agent; invariant -> script) and **shift-left** (validate data before the expensive build). Each script gate prints a scorecard fragment ending in one machine-read `STATUS: ALL-PASS|BLOCKED`. `final_gate.py`'s own closing `STATUS:` line is richer, because "shippable" has shades: `ALL-PASS - shippable`, `ALL-PASS - shippable (PASS-WITH-REMEDIATION: n finding(s) raised and fixed in-window)`, `DEGRADED` (judgement reviewers not run, `--no-reviews`) or `BLOCKED - do not ship`. **Everything beginning `ALL-PASS` exits 0 and ships**; `BLOCKED` and `DEGRADED` do not.

Each judgement reviewer writes **`reviews/round1/<gate>.md`** listing its findings. (A flat `reviews/<gate>.md` is honoured as round 0.) There is ONE review pass.

Paths below: `<W>` is the **work dir** (`2. Work Files` in the three-folder project layout, so `reviews/` and every scorecard live there), and `final_gate.py --deliverables` points at the **output** folder (`3. Output`, or `<W>/deliverables` on a legacy `--folder`/`--work` run). `run.py` prints both, fully quoted, in its exit-0 hand-off - copy them rather than reconstructing them.

## The QA window: reviewers PROPOSE, the orchestrator IMPLEMENTS, then deliver

Three steps, and that is the whole shape:

1. **Reviewers propose.** The isolated, blind gate batch runs concurrently - one gate, one fresh agent - and each returns FINDINGS.
2. **The orchestrator implements.** It fixes what the reviewers found and records what it changed.
3. **Deliver.**

There is no second review pass, no adjudication round, no round budget, and **no verdict-word gating**. The previous design (`record -> fix -> adjudicate -> resolve -> deliver -> final_gate`, gated on per-gate verdict words with a two-round budget) produced three ship-blockages on one live run that were all mechanism failures rather than data problems: the `PASS-WITH-REMEDIATION` escape hatch read blocking findings from a round that is empty by construction, so a fully repaired and source-verified pack still printed `BLOCKED`; `qa-round resolve` refused unless the artefact had moved since a fingerprint stamped *after* the repairs, so it was unreachable in the documented order and a Gaps Report shipped a "Known limitations" line asserting a defect the pack no longer had. The data work - five genuine findings, all fixed - was the small part.

### What each reviewer writes

- **Findings must be machine-actionable.** One line each:
  `- <blocking|advisory>: property=<id|-> field=<field|-> issue=<one sentence> action=<one sentence>`
- **Every finding line must be labelled `blocking:` or `advisory:` — the REVIEWER decides, and nothing downstream re-judges it.** `gate_runner.py qa-round record` reads your label verbatim; it never inspects the issue text to guess severity, because judging a novel defect on an unseen deck in an unseen language is a reviewer's call, not a regex's. (An older `- [HIGH|MED|LOW] …` line is still read, mapping HIGH to blocking.) Rubric:
  - **`blocking:`** — the deliverable makes a **false claim** or is **structurally broken**: a fabricated or untraceable value, a swallowed source disagreement, a wrong-province bind, a mis-bound or wrong-property Site Plan, a wrong property's photo, a `tbd` shown as blank or as a real value, zero cards, a real console error.
  - **`advisory:`** — a **matter of degree**, above all on byte-frozen chrome: layout, spacing, crowding, clipping, overflow, colour, a carousel slide that could be nicer, house-term preferences, and every `[ENV]` note.
  - An unlabelled finding is reported back as unlabelled and is **not** classified for you — add the label and it is counted.
- **A reviewer that finds nothing writes the explicit line `FINDINGS: none`.** Silence is indistinguishable from a crashed or truncated review, so `final_gate` treats a file with neither a labelled finding nor that sentinel as a FAILURE. This is the successor to the old "no parseable VERDICT line is a block" rule.
- **`VERDICT: <word>` is now OPTIONAL and ignored.** Write one if it helps you think; nothing reads it.

### What `final_gate.py` enforces

- every expected reviewer produced a **parseable findings file** — so the review cannot be skipped;
- **every `blocking:` finding has a recorded resolution**, else BLOCK, naming each one. This is the one safety property carried over from verdict gating, and it is why the restructure is not simply "stop checking": a `blocking:` finding is by the reviewer's own rubric a FALSE CLAIM, and a knowingly false claim may not ship because the review pass is over. What changed is what counts as *addressed* — the orchestrator RECORDING what it changed (`qa-round resolve --id <id> --because "…"`, a written reason in the audit trail), not a second reviewer re-blessing it;
- **advisory findings are CARRIED** into the Gaps Report's "Known limitations (reviewed and accepted at QA)" and never block. An advisory is closed by being written into the report, not by being fixed;
- the mechanical gates, the freeze, the four deliverables, and the Known-limitations currency check, all unchanged. **Run `deliver` BEFORE `final_gate`:** the gate BLOCKS when the delivered "Known limitations" is not the recorded pass's carried list, because a report written before the last change is a false statement in the honesty document. The remedy is ONE `deliver.py` re-run, printed with the slug, filename, `--out-dir` and `--marker-dir` already derived.

`qa-round` has exactly three modes: `record` (read the reviewers' labels), `status`, and `resolve` (record a repair). `record` is idempotent and never refuses; `resolve` requires the id to name a finding actually raised and a reason of at least 20 characters, and does **not** require the artefact to have moved.

## G-i18n - the blind localisation render-quality rubric (Cowork-only)
G-i18n confirms the rendered chrome reads as a fluent, correct, complete dashboard in the chosen language. It has two halves, exactly like the other gates: a **deterministic FLOOR** (`gate_runner.py i18n`, in the post-build sequence and the eval battery on this dev host) and a **blind LLM rubric** that is the LIVE counterpart and **runs ONLY in Cowork** (the orchestrator dispatches the sub-agent; this dev host builds + locks the scaffolding). The floor catches the structural failures that need no reader (a missing/extra key, an unfilled token, a malformed locale, a translation that silently collapsed to English, a dropped placeholder); the blind rubric judges the things only a fluent reader can.

**Who:** an ISOLATED reviewer who is **NOT the translator** (independence), reading the rendered dashboard (or the `const UI` object) for language X. Applies to BOTH bundled languages AND Phase-2 fallback languages.

**Confirms:**
- **Fluent + grammatically correct** in X (idiomatic, not word-for-word machine output; correct gender/case/agreement).
- **Complete:** no English chrome left, EXCEPT the legitimate invariants that stay verbatim in every language - `CBRE`, `OSRM`, `BREEAM`, `HGV`, `PPS`, `EU27`, `REIT`, `km`, the `%` unit, the `tbd`/`—` sentinel, and proper nouns/units that come from DATA.
- **House terms:** the real-estate / logistics vocabulary reads as standard LOCAL-MARKET usage (clear height, GLA, headline rent, overhead/sectional doors, service charge, rent-free period, landlord-vs-lessor, the local REIT cognate - SOCIMI/SIIC/etc.). Confirm against any CBRE local glossary; a defensible house-preference difference is a finding/AMBER, not a RED.
- **Placeholders/entities intact:** `{area}`/`{unit}` survive in the KPI sub-labels; `&amp;`/`&lt;`/`&gt;` entities and any leading glyph (the `●` bullet) are preserved; the `${...}` count-interpolations read correctly with a number spliced in.
- **DATA + sentinel untouched:** no property/developer/landlord/region/city/POI name, figure, date, source citation, or the `tbd`/`—` sentinel was translated. (A translated DATA value is a RED - same class as a fabrication, because it corrupts the audit trail.)

**Output:** `pass` / `pass-with-notes` / `fail` + a term list (each questioned term: the rendered string, the issue, the suggested local-market term). In the `final_gate` verdict form: `green` (fluent + complete + house terms right), `amber` (pass-with-notes: defensible house-preference differences, minor stylistic notes -> the Gaps Report), `red` (English chrome leaked beyond the invariants / a DATA value translated / a grammar error a native reader would call wrong / a dropped placeholder). A leaked-English or translated-DATA finding is HIGH -> red.

## Independence + model/effort
Model matched to risk: **G-honesty and G-trace = Opus/High** (a wrong answer ships fabricated data - the worst failure); **G-images, G-visual and G-enrich = Sonnet** (image-match, layout, and - now the workforce snapshot is dataset-sourced rather than researched - the lighter enrichment check are easier, much faster judgements). **Reserve Opus for those two fabrication-risk reviewers only; run the orchestration itself and the gate re-checks on Sonnet** (the run's biggest token sink is the orchestration, and most of it - intake adjudication, photo-match, finding triage - does not need Opus). Mechanical scripts gate first so judgement agents never spend tokens on data that fails the free checks. **Scale reviewer EFFORT to risk (this is about depth, never about independence).** When the artefact is clean on its face - a token-clean build, a workforce block that is 100% bundled-dataset-sourced with current dates and a plausible derived share - the reviewer confirms quickly and returns few or no findings (or `FINDINGS: none`); it does not re-derive from scratch. The instant it sees an anomaly (a figure that smells copied, a placeholder with discarded candidates, a value absent from the source), it switches to full scrutiny. A fast confirm on genuinely clean data is correct, not a shortcut; a thorough hunt the moment something is off is mandatory. (G-enrich especially: post-v11 the snapshot is dataset-sourced, so the common case is a fast confirm, the exception is a researcher-overridden figure that gets the full source/recency check.) Reviewers never edit the artefact - they PROPOSE findings; the orchestrator applies the fix and records it. There is no re-review. A defect fixed in the template (not the data) means bumping the template version (`reference/template-contract.md`).

## Reviewer dispatch contract (context independence) - MANDATORY
Each judgement reviewer must be **fresh-context and blind to the orchestrator's view**. This is non-negotiable: a reviewer that inherits the orchestrator's reasoning is not independent, and the gate is then theatre.

1. **Fresh context.** Dispatch each reviewer as a separate `Agent` sub-agent (one gate = one agent). It inherits NONE of the orchestrator's conversation; it starts from an empty window. Never reuse a single agent across gates (judging honesty and visual in one head cross-contaminates).
2. **Blind dispatch.** The prompt the orchestrator hands the reviewer contains ONLY:
   - the **path(s)** to the artefact under judgement (`canonical.json`, the built `.html`, or `render/*.png`), which the reviewer **opens and reads itself** - never paste the orchestrator's summary of it. For the DATA reviewers (G-honesty / G-trace / G-enrich) hand them `work/canonical_review.json` - a photo-stripped twin regenerated on EVERY freeze, including a manual re-freeze after an out-of-band data fix, so a re-review can never read a stale twin (the base64 heroes are ~99% of the multi-MB `canonical.json` and only burn the reviewer's context); `canonical.json` stays authoritative and the contact sheet is the image aid for G-images;
   - the **gate rubric** (the checklist from this file / `reference/visual-qa.md`) and, where relevant, `templates/canonical.schema.json` or the `assets/reference_screenshots/` baseline.
   - **for the decision-correctness checks (G-trace / G-honesty), C's two machine diffs and their evidence**, which the DATA reviewer opens read-only itself: the tracker `work/extract/*_map.json` + the matching `work/extract/*_mapcheck.json` (the second blind map; the `semantic_disagreements` are surfaced in `work/yield_report.md`), and `work/match_decisions.json` + `work/match_verify.json` (the author and the blind verifier verdicts; the `match disagreement` lines ride `meta.conflicts`), alongside `source_ledger.csv` (the basis assumption is in `source_locator`) and the pre-merge `work/extract/*.json` source records. These are the **decision's own audit trail and a machine SECOND-PASS DIFF, not the orchestrator's view** - the reviewer SEES C's diff but still re-derives the basis/verdict from the raw rows/records itself and forms its OWN verdict; the MUST-NOT-CONTAIN list below is unchanged.
   It MUST NOT contain: the orchestrator's own findings or opinion, an "expected" answer, "I believe this is correct / fine", which fields the orchestrator thinks are weak, or what any previous reviewer concluded. The reviewer re-derives its judgement from the artefact alone.
3. **Findings only, written by the reviewer, into the round directory.** The reviewer writes **`reviews/round1/<gate>.md`** listing its findings, each labelled `blocking:` or `advisory:`, or the single line `FINDINGS: none` if it found nothing. A `VERDICT:` line is optional and ignored. Create the directory if it does not exist. The orchestrator never writes or edits a reviewer's file, and never self-certifies a gate over data it authored.
4. **ONE review pass. The reviewers PROPOSE; the orchestrator IMPLEMENTS.** There is no second discovery pass and no adjudication round. The blind batch runs once, exactly as rules 2 and 6 describe - fresh context, no memory, no orchestrator view, its question is "what is wrong?" - and then the orchestrator fixes what was found and RECORDS each repair with `qa-round resolve --id <id> --because "<what you changed>"`.

   **A `blocking:` finding must be addressed before the pack ships.** `final_gate` blocks while one has no recorded resolution, naming it. That is deliberate and is the only gate-like rule left: a `blocking:` finding is a FALSE CLAIM by the reviewer's own rubric, and shipping a knowingly false claim because the review pass ended is not acceptable. **Advisory findings are carried**, not fixed and not re-reviewed - they ship in the Gaps Report's "Known limitations".

   Why no verification pass: the two-round design it replaces cost three ship-blockages on one live run that were all mechanism failures rather than data problems (a remediation escape hatch reading a round that is empty by construction; a `resolve` freshness guard that made recording a repair impossible in the documented order). Recording a repair, with a written reason in the audit trail, carries the accountability the adjudication round was there to provide, at one command instead of a dispatched agent plus a data diff.
5. **DEGRADED mode is labelled.** If the skill is run in plain chat with no sub-agent dispatch available, the "reviewer" is the same context as the author: independence is lost. Say so plainly, mark the run DEGRADED, and treat the verdicts as self-review, not independent QA. This applies with FULL force to the decision-correctness checks: without dispatch, C's second map / match passes cannot run blind (no `*_mapcheck.json` / `match_verify.json`) and the G-trace/G-honesty decision re-derivation is the author re-reading its own work - label it self-review explicitly, never independent.
6. **Parallel dispatch (faster, and MORE independent).** Dispatch a phase's reviewers **concurrently** - all of a phase's `Agent` calls in a single message - not one after another. This is strictly safe and actually strengthens independence: when they fire together no verdict exists yet, so none can be biased by another's conclusion. Two hard rules make parallelism quality-neutral:
   - **Still one gate = one agent.** Never collapse gates into a single "review all dimensions" agent to parallelise - that destroys independence. Concurrency means N separate fresh agents at once, each with its own rubric and its own `reviews/round<N>/<gate>.md`.
   - **Freeze the artefact around the window.** `run.py` freezes `canonical.json` AUTOMATICALLY when the pre-build mechanical scorecard is ALL-PASS (and deletes a stale snapshot when it is blocked), so the snapshot exists before you dispatch reviewers without a manual step; re-running `gate_runner.py freeze <canonical.json>` by hand is only needed after an out-of-band edit - and that re-freeze now ALSO regenerates the photo-stripped `canonical_review.json` twin, so re-dispatched DATA reviewers can never read pre-fix data (this closes the wasted duplicate-review-round). After collecting verdicts, `gate_runner.py freeze <canonical.json> --check` must pass - this proves every concurrent reviewer judged byte-identical bytes and that no edit slipped in mid-review. `final_gate.py` re-checks this (skipped only in `--no-reviews` DEGRADED mode). Pre-build reviewers (G-honesty, G-trace, G-images, **and G-enrich when `regions` were enriched**) run in one concurrent batch against the frozen `canonical.json`; G-visual runs post-build against the built HTML. (`final_gate.py` requires a `G-enrich.md` verdict whenever regions ran, so it must be dispatched in that batch - omitting it deadlocks the final gate.)
