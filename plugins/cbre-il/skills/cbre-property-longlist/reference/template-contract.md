# The template contract

The dashboard is produced by injecting three data blocks into a **frozen, versioned** template. The chrome (fonts, CSS, Leaflet, render JS) is byte-stable across every project; only data and a handful of config strings change. This is the whole value proposition - the CBRE look cannot drift.

## The template asset
`assets/dashboard_template.html` was originally generated from a reference dashboard by `helpers/make_template.py` (a HISTORICAL path now - see Versioning), which:
1. replaces the three data lines with markers: `/* @@INJECT:PROPS@@ */`, `/* @@INJECT:POIS@@ */`, `/* @@INJECT:REGIONS@@ */`.
2. replaces project-specific strings with `{{tokens}}`: `topbar_meta`, `eyebrow`, `title_html`, `lede`, `footer_copyright`, and the KPI tokens (`kpi_properties`, `kpi_countries`, `kpi_regions`, `kpi_developers`, `kpi_wh_area`, `kpi_rent`, `kpi_countries_sub`, `kpi_regions_sub`, `kpi_wh_area_sub`, `kpi_rent_sub`). The authoritative token list is `_common.CONFIG_TOKENS`.
3. applies robustness `POST_PATCHES` (so a missing numeric shows `"tbd"` instead of crashing the render).
4. writes `assets/VERSION` (`<label>` + `chrome_sha256`).

Every replacement must hit exactly once or `make_template.py` aborts - the 11 MB file is never hand-edited blindly.

## Build = forward substitution (`build_dashboard.py`)
`render(canonical)` fills the `{{tokens}}` (hero strings from `meta.hero`; KPIs **computed from the data** so they cannot drift) and replaces the three markers with `const NAME = <minified-json>;`. It asserts no token or marker is left behind. The output is, by construction, the template plus exactly these substitutions.

## Byte-stability check (`gate_runner.py validate-html`)
Re-runs `render(canonical)` and asserts the delivered file is **byte-identical**, that the three blocks round-trip a JSON parse, and that the template's SHA matches `VERSION`. Any chrome change therefore fails the gate unless the template was deliberately re-versioned.

## Versioning
When a visual/template defect must be fixed (not a data fix), the template is **HAND-EDITED - that is the blessed, normal path**. `make_template.py`'s regenerate/patch machinery is HISTORICAL: the raw reference HTML is not on disk, and `--patch-only` applies only to the pre-i18n (v18) shape - which is no longer kept anywhere - so it can never rebuild the live template (v5-v18 were already hand-applied for the same reason).

**The hand-edit order is load-bearing** (skipping a step has cost real incidents):
1. take a dated copy of the whole skill folder FIRST (it is not a git repo - the copy is your only revert);
2. edit `assets/dashboard_template.html`;
3. bump `assets/VERSION` with the **CRLF-normalised TEXT hash** (`Path.read_text` - NOT the raw-byte hash `integrity.json` records; the two hashes differ on the same file, and putting the raw hash in `VERSION` blocks every run at exit 7);
4. `python helpers/make_integrity.py`;
5. run the evals - `smoke_test.py` (three blocks round-trip, byte-stable chrome), `i18n_test.py` (template<->EN key lockstep), `compare_test.py`/`flyover_test.py`/`numguard_test.py`/`areaunit_test.py` (the pinned per-version behaviours) - and land a NEW eval that pins your fix;
6. add the version's summary line below. `validate-html`'s SHA check then enforces the new version on every client run.

The version is pinned by `assets/VERSION` (label + `chrome_sha256`) and enforced by `validate-html`'s SHA check - not by any `project.yaml` key. Three breakdown shapes are handled - a leading summary clause plus a parenthesised `;` list; a bare `;` list with no summary (`"Main Office 15,213 sq ft; Hub Office 3,975 sq ft; ..."`); and a `;` list whose items own their trailing qualifier (`"14,486 sq ft (ground floor); 15,592 sq ft (first floor)"`, which survives because the split is depth-aware). **The guard is what makes this safe:** the breakdown path is entered only when the string carries a LETTER - exactly the case where `officeAreaStr` already falls back to the string - so a bare number, an absent value and the `tbd` sentinel return `officeAreaStr(p)` byte-for-byte and the numeric twin can never be overridden. `officeAreaVal`, `glaVal` and the rent formulas are untouched; **this is display only**. Two deliberate design calls: (1) **Compare KEEPS the flattened string** - a five-item list in one matrix cell sets the row height for every column and destroys the side-by-side scan (v37's `short_motorway` reasoning); (2) magnitudes are **NOT re-formatted**, only the unit is appended, and only to a fragment with no letter of its own, so `"Main Office 15,213 sq ft"` can never collect a second unit (v28's caution, the 10.76x family) and `"1.711"` is never silently restated as `1,711`. A 1-2 digit tail is never read as an area, so `"transport office 2"` stays a NAME rather than becoming a 2 sq ft room. **Zero new i18n keys** - no prose was authored, so the EN/template lockstep is untouched. Eval: `evals/office_breakdown_test.py` + `.mjs` (executes the real `officeAreaHTML`/`detailHTML`/`compareHTML` in `node:vm`, including the escaped-vs-real-markup assertion the whole fix stands on); `areaunit_test`'s site register updated in lockstep, and `district_field_test`'s literal `v38` pin softened to `>= 38`.

## Generalising to a new reference look
Point `make_template.py` at a new reference HTML and update the `CONFIG_REPLACEMENTS`/`POST_PATCHES` literals to match that file's exact strings. The data schema is shared, so only the chrome changes.
